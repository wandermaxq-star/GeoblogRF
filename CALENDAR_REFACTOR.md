# Рефакторинг модуля "Календарь событий"

Этот документ отслеживает процесс полного рефакторинга и интеграции функционала календаря событий непосредственно в карту.

**Основная цель:** Упразднить отдельную страницу `/calendar` и создать более цельный и интуитивный пользовательский опыт, где события являются неотъемлемой частью карты.

---

## 1. Ключевые изменения и цели

-   [x] **Упразднить страницу `/calendar`**: Полностью удалить страницу и связанные с ней маршруты.
-   [x] **Интегрировать в карту**: Функционал календаря и событий будет доступен через боковую панель на десктопной версии карты (`EventPanel`) и через "шторку" (`EventBottomSheet`) на мобильной.
-   [x] **Упростить создание событий**: Создан `AddEventModal` — простое модальное окно с карты.
-   [x] **Упростить архитектуру**: Весь внутренний navigate('/calendar') заменён на `setLeftContent('map') + setRightContent('calendar') + navigate('/map')`. Маршрут `/calendar` → редирект на `/map`.
-   [x] **Улучшить UX**: Клик по событию в новых компонентах центрирует карту без лишних переходов.

## 3. Зависимости и особые моменты

-   **Геймификация**:
    -   Источник XP: `CREATE_EVENT`.
    -   Действие: Создание события.
    -   Логика должна быть перенесена из `CalendarPage.tsx` в `AddEventModal.tsx`.

-   **Модерация**:
    -   Администраторы должны иметь возможность просматривать, редактировать и одобрять/отклонять события.
    -   Текущий интерфейс модерации может сильно зависеть от страницы `/calendar`. Требуется тщательный анализ и, возможно, временное сохранение старого интерфейса только для админов.

-   **Избранное**:
    -   События сохраняются в `FavoritesContext`.
    -   Нужно убедиться, что при клике на событие в панели избранного происходит корректное центрирование на карте.

-   **Типы данных**:
    -   Проверить, что `MockEvent` и `ExternalEvent` по-прежнему корректно используются во всей системе после удаления основного конструктора. Возможно, получится упростить и эти типы.
